# 100 — Live loader probe (2026-10-26): block size, MCT, boot mode, 0xDC

Status: **live, read-only** probe on the spare 64 GB unit. Only channel-2 queries
were issued (`0xB1`, `0xB4`, `0xD9`, `0xDC`, `0xDE`); nothing was written to eMMC,
NVRAM or RPMB. The unit was rebooted back to TabletOS afterwards.
Tool: `analysis/probe_loader.py`. Captures:
`analysis/playbook-live-spare-2026-10-25/loader-probe/`.

## 1. Live MCT (`0xD9`)

Magic `0x92BE564A`, minor `0x0018`, major `1`. TLV layout is `{u8 type, u8 length}`
with `length` including the two header bytes; range payloads are
`{u16 dummy, u32 start, u32 end}` in 64 KiB blocks.

| type | name | start | end |
|---|---|---:|---:|
| `0x1D` | Flash chip | 0 | `0xFFFFF` |
| `0x31` | User MMC | 5 | `0xFFFFF` |
| `0x18` | Bootrom | 5 | `0xC` |
| `0x34` | **MBR** | **`0x805`** | **`0x814`** |
| `0x1B` | **OS Fixed** | **`0x815`** | **`0x4804`** |
| `0x1E` | OS NV (NVRAM) | `0x4805` | `0x4844` |
| `0x36` | — | `0x4845` | `0x4904` |
| `0x1C` | **FS Fixed** (UFS) | **`0x4905`** | **`0xFFFFF`** |
| `0x35` id 0 | **QNX region 0 (`hd1`)** | `0x815` | `0x2804` |
| `0x35` id 1 | **QNX region 1 (`hd2`)** | `0x2815` | `0x4804` |

**There are no `0x39` entries** (confirmed against `hd4.bin`; the live prefix is
identical). Consequently the loader's **path 2 cannot resolve a partition by
`PartitionID == 8`**, and `bb10mt flash` (which builds `_type=8`, `rrcq.offset=0`)
will not address the IFS on this unit. The tool must use **path 1**:
`dest = p34.start + rrcq.offset`.

For the region-0 IFS:

```
p34.start            = 0x805
region-0 IFS block   = 0x825
rrcq.offset          = 0x825 - 0x805 = 0x20
rrcq.Count           = 44 blocks (0x2C)   (0x2BFE10 padded to 0x2C0000)
media byte           = 0x08250000
LBA512               = 0x41280
gate                 : 0x1B {0x815..0x4804} contains 0x825..0x850   ✓
```

Region 1 is `0x35` id 1 (`0x2815..0x4804`); `0xF8` path 1 re-bases from the end of
the previous region (`98` §2.3), so its offset is not simply `0x2825-0x805` — compute
it from the code before using `0xF8`.

## 2. Boot mode

`0xDE` action 0 returned `status=0, mode=1 (FACTORY), count=50`. This is an
independent confirmation of `95`: the unit is armed in factory mode and the counter
is the budget. The loader read cannot distinguish a sentinel, but the count is the
real value here.

## 3. `0xDC` is not zlib CRC-32

`0xDC {0x825, 0x2C}` → `0xBB454844`.

- `zlib.crc32(media[0x08250000 : +0x2C0000])` = `0x0283B97A` — no match.
- 44 sectors (22,528 B) = `0x1A2E8F6F`; 0x2BFE10 B = `0x2144DF1C` — no match.
- The handler at `0x8011AE9C` (ARM) calls the same gate `FUN_80100118(address, 0,
  length)`; the hash itself is computed before that and is not the MCT CRC routine.

**Consequence:** `98` §9.5's "compare `0xDC` with `zlib.crc32`" is wrong. Use `0xDC`
as a **relative fingerprint** (before vs after a write), and treat the bootloader's
CRC gate after reboot as the authoritative verification. Reversing the hash is a
small follow-up (disassemble the 0xDC case's pre-gate code).

## 4. Corrections to `98` / `99`

| claim | correction |
|---|---|
| `bb10mt flash` (path 2, `_type=8`) works | **No** — the live MCT has no `0x39` entries. Use path 1 with `rrcq.offset=0x20`. |
| `0xDC` CRC is zlib-compatible | **No** — observed `0xBB454844` ≠ zlib. Relative fingerprint only. |
| BS is a RAM unknown (U3) | **Closed**: `0xB1` dword 1 = `0x00010000`. |
| MCT source unknown (U1) | **Closed**: the live `0xD9` prefix equals `hd4.bin`. |
| `0x39`/path-2 viability (U2) | **Closed**: no `0x39`; path 2 is unavailable. |
