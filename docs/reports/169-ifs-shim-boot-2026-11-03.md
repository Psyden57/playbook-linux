# 169 — The shim IFS boots: uncompressed 2.1.0.1917 IFS + 1917 RCFS on the reference

Status: **measured on the reference unit, 2026-11-03.**  The image built in
session 24 (IFS-REBUILD.md milestones 1–3) was flashed and **booted**; `/base`
is the 1917 RCFS and the running `/proc/boot/rfs_validator` is our 8,759-byte
shim.

## Answers in brief

* **The uncompressed IFS boots.**  The loader accepted `flags1 = 0x01`
  (`COMPRESS_NONE`) and the stock prefix's compressed `stored_size`
  (`0x3150c0`) did not block it.  This answers the two IFS-REBUILD §4 unknowns
  that needed a boot.
* **The shim does the mount.**  `/dev/hd1t179 on /base type qnx6`, with
  `/base/etc/os.version` = `2.1.0.1917`, and `/proc/boot/rfs_validator` is
  8,759 B (stock: 50,554 B).  `rfs_validator` is no longer in the path.
* **The CRC path accepts the length patch.**  The image is
  `0x788D84` bytes, `os_type` 6, CRC `0x38EE7B46`; the loader booted it.
* **`bbusb.py flash` ran on hardware for the first time** and is now the
  flasher that wrote this unit.  It sent one 363,790,928-byte container
  (RCFS + IFS), 22,232 frames, signature `0x40F9`, `COMPLETE 0x40C0`, exit 0.
* **The 1917 OS login is `devuser` only.**  The 4869 root key is rejected by
  1917; `PB_USER=devuser tools/pbssh.sh …` works.

The run list was checked against the vendor `PlayBook_2.1.0.1917.signed`: the
RCFS runs are **identical**, and the V2 offsets are component-relative as in
the vendor container.  The loader expands each sparse run to its partition
(operator), which is why the sparse container is correct.

## 2. The write, including two failed attempts

The successful command (as the **user**, no `pkexec`):

```
while ! lsusb | grep -q '0fca:0001'; do sleep 0.5; done
python3 tools/bbusb.py flash --signed local/work/pair.signed \
    --from-bootrom --password 0000 --apply --debug
```

Result: `363790368/363790368 payload bytes, seq 22231`,
`0x40F9 signature -> cmd 0x4006`, `COMPLETE 0x40C0 -> cmd 0x4006`, `done`,
exit 0.

Two failures before it, both tooling, neither wrote media:

1. **`pkexec` is wrong here.**  `/dev/bus/usb/003/0NN` is
   `crw-rw-rw-+` with `user:psyden:rw-` (udev uaccess), so the user can open
   the device.  `pkexec` runs as root, which does **not** have the user's
   `pyusb` (`~/.local/lib/python3.14/site-packages`), so the first attempt died
   with "pyusb is not installed".  A `PYTHONPATH` would have made it work, but
   it is unnecessary.
2. **Killing the `pkexec` wrapper left an orphan root `bbusb.py`** holding the
   USB interface.  The user then got `set_configuration(1) -> Resource busy`
   / `claim_interface(0) -> Resource busy`, and the ramloader was left
   unresponsive (`0x80EF`/`0xEF` all `-110`).  A **power-cycle** cleared it;
   no media had been written (the flash had failed at loader init, before
   PreFlash).  `ps -ef | grep bbusb` is the check.

The successful run started with the unit already in the ramloader (`0x8001`):
`bbusb.py flash` found it, initialised it, and did PreFlash + frames.

## 4. What this settles

* **Uncompressed IFS**: accepted.  `flags1 = 0x01` is honoured; the stock
  `stored_size` (compressed size) did **not** truncate or block the image.
* **CRC length**: `LoadEnd = LoadStart + 0x788D84` with the end-8 cookie and
  the recomputed CRC boots on the factory path.
* **The shim**: `rfs_validator` may be replaced by a program that mounts
  `/base` read-only and exits 0.  `/base` no longer needs a valid signature.
* **No RCFS signature needed**: the `.3.sig` block at `0xF0000` was left stock
  (4869) and is irrelevant with the shim.
* **`bbusb.py flash`**: hardware-proven for a 363 MB container and a 121-block
  component in one `--signed` file.
* **The 1917 OS** boots against the **4869 UFS** (`/dev/hd3 on /`).  The UFS
  version mix did not block the boot to a working OS; it is still a second
  variable and the matching 1917 UFS is a later step.

## 5. Open items and next work

* **Bloatware removal** can now proceed in `/base` (a custom 1917 RCFS with the
  same triple: IFS unchanged, RCFS rebuilt, one flash).  Keep the IFS and the
  RCFS as separate variables in the *container* even though they ship together.
* **The matching 1917 UFS** (`PlayBook_2.1.0.1917.5.ufs`) is the second
  variable to remove.
* **`BOOTCTR_FCTRY`**: the OS boot tops it up; `devuser` could not read
  `/dev/rpmb` and no root login exists on 1917 yet.  Read it read-only before
  the next flash if a value is needed.
* **No RPMB write was made.**  The flash is media (region 0), not RPMB.

## 6. Bench notes that changed

* **Use `devuser` on 1917**, not root: `PB_USER=devuser tools/pbssh.sh …`
  (`tools/pbssh.sh` now takes `PB_USER`; `tools/pbscp.sh` already did).
* **Do not `pkexec` the USB tools.**  The device node has a user ACL; root
  lacks the user's `pyusb`, and a killed `pkexec` can leave an orphan holding
  the interface.  Kill any orphan by PID (it needs root to kill), then
  power-cycle the unit if the ramloader is wedged.
* **The ramloader can wedge** after an aborted handshake; `0x80EF`/`0xEF` all
  time out and only a power-cycle clears it.
* **`bbusb.py flash --from-bootrom` opens for 10 s.**  Arm a
  `lsusb | grep 0fca:0001` wait first, then start it, or run it with the unit
  already in the ramloader.
