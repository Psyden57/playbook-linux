# 207 — A debloated 2.1.0.1917 QNX image as a live hardware oracle (session 43)

Date: 2026-11-12 (session 43, Linux-era 37).
Bench: the unit is on the **minimal 1917 reference OS** built here, reachable over
USB with `tools/QCL.py` to `169.254.0.1:9090`.  No RPMB/NVRAM/MCT write; the
`BOOTCTR_FCTRY` top-up ran and the record read `0x32` (operator read of the low
byte = `'2'`).

## 0. Headline

The two 2.1.0.1917 region-0 components are now a **minimal, bootable QNX
reference** whose only jobs are to bring up the USB network, run `qconn` on
port **9090**, and give us a shell/`exec` channel to inspect the hardware:

```
QNX localhost 6.6.0 2014/03/19  OMAP4430_ES2.2_HS_Winchester_Rev:07
qconn: 169.254.0.1:9090      host: enp8s0f3u1 169.254.0.2/16
```

It boots in ~30 s to USB enumeration and answers `tools/QCL.py info` /
`exec` immediately.  This is the oracle for the MCLK1/audio question and for
any HAL/GPIO/I²C comparison: run the reference's own code and read what it
actually does to the registers, instead of inferring it from Linux.

## 1. What was changed (two variables, staged)

The vendor components are untouched; everything is done on a **copy** of the
RCFS, mounted read-write with `bb10mt qnx6 mount` (an OS 2.x `.rcfs` is a QNX6
filesystem; `rcfs_extract.py` is for BB10 `.rcfs` only).  The IFS is the
session-24 **rfs_validator shim** image, unchanged — the stock validator checks
the RCFS signature, and any edit invalidates it.

### Stage A — the minimal service set (verified first)

`/base/scripts/startup.sh` is the stock script with only its four
`RUN_LEVEL_*_SERVICES` lists reduced, plus two hooks after
`start_runlevel FINAL`:

```sh
RUN_LEVEL_0_SERVICES=" filesystem pps random pty net powerman phyctrl usbmgr rimusb"
RUN_LEVEL_1_SERVICES=""
RUN_LEVEL_2_SERVICES=""
RUN_LEVEL_FINAL_SERVICES=""

# after start_runlevel FINAL:
if [ -x /accounts/devuser/startup.sh ]; then /accounts/devuser/startup.sh & fi;
/base/usr/sbin/qconn port=9090 &
```

Why each service is needed:

| service | why |
|---|---|
| `filesystem` | creates `/bin`,`/lib`,`/usr`… symlinks and mounts the UFS (`/accounts`), so the top-up script and the door's home exist |
| `pps` | the PPS filesystem; `nvram_resource_manager` publishes `deviceinfo` into it |
| `random` | `/dev/random` (the USB stack/door use it) |
| `pty` | `/dev/ttyp*` (a serial console / sshd later) |
| `net` | io-pkt, which owns the USB ECM interface |
| `powerman` | power management; `phyctrl` asks it to power the USB PHY |
| `phyctrl` | `winchester_phy_ctrl` turns on the USB PHY + OTG controller clock — **required for enumeration** |
| `usbmgr` | `RIM_usbmgr-Winchester`, creates `ecm0` at `169.254.0.1` |
| `rimusb` | the USB device-mode driver |

`qconn` is not a service: it is started directly (`port=9090`) and is
**unauthenticated** — this is a bench image, not a product.  No `qconnDoor`,
`sshd` or `authman` is needed.

The hook that actually does the useful work is the **UFS's**
`/accounts/devuser/startup.sh` (the operator's automation, on the 1917 UFS):
it tops the counter up, turns dev mode on, drops the packet filter, mounts
`/accounts/devuser/fs1.qnx6` on `/q`, `slay`s and restarts `qconn port=9090`,
and starts `sshd -D` as root with `/accounts/devuser/sshd_config`
(`PermitRootLogin yes`).  So the minimal `/base` does not have to start either
`qconn` or `sshd` itself; the explicit `/base/usr/sbin/qconn port=9090 &` line
is a harmless fallback (the UFS script re-starts it).  `sshd -D` and
`sshd-watchdog.sh` in `pidin arg` come from there, not from the `/base`
service set.

**Cleaned (session 43).**  The UFS `/accounts/devuser` automation was reduced
to what the oracle needs.  `startup.sh` now does only the top-up, dev mode, the
packet-filter drop, `qconn port=9090`, and root `sshd` (with
`/accounts/devuser/sshd_config`, which has `StrictModes no`).
`restart-launcher.sh`, `sshd-watchdog.sh` and `symlink.sh` were removed and
`launcher-secure` is killed.  The host's `local/secrets/rsa.pub` was written to
`/accounts/devuser/.ssh/authorized_keys`, so **`tools/pbssh.sh` gives root
(`uid:0`) without the door** (`/var/etc/ssh/ssh_host_rsa_key` already exists).
`dd` is `/base/bin/dd`; the symlink overlay is not needed for the top-up.

### Stage B — the filesystem prune

Deleted from `/base` (the live filesystem dropped **314.9 → 90.4 MiB**):

`air`, `appinstall`, `opt`, `usr/fonts`, `usr/hmi`, `usr/photon`,
`usr/carrier`, `usr/include`, `usr/lib/{browser,ema,graphics,pim,python2.7,
python3.2}`, `usr/share/{wallpaper,webkit-owb,sounds}`, `seed/bars`,
`lib/firmware`, and the huge `libwebkit*`, `libicudata*`, `libplayready*`,
`libcascades*`, `libflashplayer*`.

Kept: `bin`, `sbin`, `lib` (incl. `lib/dll` — all drivers, the WM8994 codec
driver and the USB ECM/RNDIS drivers), `usr/bin`, `usr/sbin`, `usr/lib` (the
loose libraries, incl. `libcrypto.so.2`, `libpps*`, `librtas*`), `etc`,
`scripts`, `seed/rootfs`, `board.tdf`, `svnrev`.  The door stack's `DT_NEEDED`
closure is satisfied by the IFS (`libc`, `libsocket`, `libhuapi`,
`libsbgse56`) plus the kept `/base/lib` (`libpps`, `librtas`).

**The flash container does not shrink** (Stage A and Stage B both pack to
363,790,928 B): `bbusb.py` skips only runs of `0xFF`, and the blocks freed by
`bb10mt` are not `0xFF`.  The pruning is a *live-filesystem* win, not a flash
byte-count win.  `bb10mt qnx6 compact` is the tool if a smaller image file is
wanted later.

## 2. Build and flash (reproducible)

```bash
# build the minimal RCFS (copies the vendor .1.rcfs, mounts the copy RW,
# patches startup.sh, prunes, unmounts, re-mounts to verify)
python3 tools/build_minimal_qnx.py            # stage B (pruned)
python3 tools/build_minimal_qnx.py --no-prune # stage A (services only)

# flash IFS (region-relative block 16 = loader block 0x825) and RCFS (192 = 0x8D5)
printf '%s=16,0\n%s=192,0\n' \
    "$PWD/local/work/ifs-shim-sealed.ifs" \
    "$PWD/local/work/minimal/rcfs-minimal.rcfs" > local/work/minimal/set.lst
python3 tools/bbusb.py pack -l local/work/minimal/set.lst -v 1,2 -s \
    -c local/work/minimal/setB.signed
python3 tools/bbusb.py parse  local/work/minimal/setB.signed
python3 tools/bbusb.py flash --signed local/work/minimal/setB.signed   # dry run
# arm the flasher, then reboot the *running QNX* with:
#   python3 tools/QCL.py exec /proc/boot/shutdown -S reboot -f
nohup python3 tools/bbusb.py flash --signed local/work/minimal/setB.signed \
    --from-bootrom --password 0000 --apply > /tmp/flash.log 2>&1 &
python3 tools/QCL.py exec /proc/boot/shutdown -S reboot -f
```

Measured on the unit: `COMPLETE 0x40C0 -> cmd 0x4006`, `done`; USB
re-enumerates as `0fca:8012` at ~30 s.

**Connect:** `python3 tools/QCL.py info` (defaults: `169.254.0.1:9090`),
`... exec /proc/boot/pidin`, `... put tools/pbi2c /tmp/pbi2c`, etc.  The host
link `enp8s0f3u1` already carries `169.254.0.2/16` — do not re-add it.

## 3. Verification

* `QCL.py info` → `MACHINE=OMAP4430_ES2.2_HS_Winchester_Rev:07`, `RELEASE=6.6.0`,
  `VERSION=2014/03/19`; `exec /proc/boot/uname -a` → the same.
* `mount` → `/dev/hd3 on / type qnx6` and
  `/accounts/devuser/fs1.qnx6` (the UFS is up).
* `BOOTCTR_FCTRY` reads `0x32` (operator read; low byte `'2'`).
* `pidin` (~98 lines) shows exactly the expected set: procnto, devc-seromap,
  slogger, pipe, trustzone, shm_lock, i2c×3, wdtkick, pmic, random,
  devb-mmcsd, spi-master, backlight_win, rpmb, nvram, displayctl, sh, pps,
  devc-pty, io-pkt, powerman, phyctrl, usbmgr, rimusb, qconn.
* Stage A (services only, files intact) booted and answered qconn; Stage B
  (pruned) also booted and answered.
* `pidin arg` shows exactly the intended services with their command lines —
  `powerman -c devpm-omap4.so … /etc/system/config/winchester.pm`,
  `winchester_phy_ctrl -U 344:99`, `RIM_usbmgr-Winchester`,
  `io-usb-dcd -d RIM_rndis_mux-…`, `rimusb`, `io-pkt-v6-hc`,
  `/base/usr/sbin/qconn port=9090` — plus `sshd -D`,
  `/accounts/devuser/sshd-watchdog.sh`, and `launcher-secure` (the **TabletOS
  GUI/app launcher**, started by `/accounts/devuser/restart-launcher.sh`) —

## 5. Way back

* **To stock TabletOS:** flash `local/work/minimal/wayback.signed` (stock
  `.4.ifs` + stock `.1.rcfs`).  The stock IFS's validator accepts the stock
  RCFS; the UFS is untouched and carries the top-up script.
* **To our Linux image:** flash `boot/chainloader/kernel.img` only
  (`--dest-block 0x825`); region 1 (the Linux rootfs) is untouched and the
  minimal RCFS at 0xC00000 is simply ignored by Linux.
* If a verification ever fails and the region is marked dirty, clear NVRAM
  `0x2074` with `tools/bbusb.py reset-osregion --apply` (SAFETY §4, report 164).
