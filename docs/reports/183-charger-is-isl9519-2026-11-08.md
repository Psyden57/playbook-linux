# 183 — The PlayBook's charger is an ISL9519 on I²C1 0x09; the TWL6030 BCI is unused

**Session 31 (absolute), Linux-era 25.  2026-11-08.**
Status: **bench, read-only on TabletOS** (1917): `pidin`, `/pps/services/power`,
`pbi2c` register reads; static strings/ELF inspection of `/base/bin/battery_win`.
No RPMB, NVRAM or media write.

This answers the session-30/31 question "why does the pack not charge under
Linux despite the TWL6030 BCI driver?"  The BCI was the wrong chip: **the
PlayBook's charger is an Intersil ISL9519**, an SMBus narrow-VDC charger at
I²C1 (`0x48070000`) slave **0x09**.  RIM's `battery_win` drives it; the TWL6030
BCI is left disabled by the stock OS.

---

## 0. Headline

* **The charger is an ISL9519 at I²C1 `0x48070000`, 7-bit address `0x09`.**
  VendorID (reg `0xFE`) = `0x0049` ('I' = Intersil), DeviceID (reg `0xFF`) =
  `0x0003`.  Vendor `battery_win` contains `isl_9519_init`,
  `isl_9519_i2c_dev_p`, "CC charging set to %d mA", "i2c_read failed to read
  ISL control register" and "isl9519.c could not open i2c device".
* **The stock OS does not use the TWL6030 BCI for charging.**  On a running
  TabletOS the MAIN_CHARGE block (`0x49`, base `0xE0`) reads
  `CONTROLLER_CTRL1 = 0x00` (EN_CHARGER clear), `CHARGERUSB_VOREG = 0x02`,
  `CHARGERUSB_VICHRG = 0x04`, `CHARGERUSB_CINLIMIT = 0x01` — the bootloader's
  reset values.  QNX only writes `CONTROLLER_INT_MASK = 0xDC` (VBUS/VAC
  detection unmasked, everything else masked).
* **The ISL9519 is configured and in CC.**  Registers read on the live unit
  (16-bit words, LO first):
  `0x14 = 0x0280` (ChargeCurrent 640 mA), `0x15 = 0x1070` (MaxSystemVoltage
  4208 mV), `0x3F = 0x0180` (InputCurrentLimit 384 mA), `0x44 = 0x0000`
  (control).  The matching `/pps/services/power/charger` values are exactly
  `ChargeCurrent 640`, `MaxSystemVoltage 4208`, `InputCurrentLimit 384`,
  `ChargingState CC`, `ConnectedChargerSource USB HOST`.
* **Why 1917 does not appear to charge from a PC USB port:** its host-port
  input limit is **384 mA**, while `InputCurrentMonitor` reads **430 mA** —
  the system load is above the limit, so the gauge shows
  `AverageCurrent = -16 mA` and the battery icon stays "not charging".  On
  the rapid-charger dock the limit is higher and the pack charges: it went
  **2 % / 3.33 V → 7 % / 3.683 V** between the Linux reading and the 1917
  reading, and QNX reports `StateOfHealth 90`, `StateOfBattery OK`.
* **Consequence for Linux:** the session-30/31 TWL6030 BCI work cannot charge
  this pack.  Linux needs an **ISL9519 driver** (no mainline driver exists) at
  I²C1 0x09: write non-zero `0x14`/`0x15` (the eval guide: the output is
  disabled while both are `0x0000`), set `0x3F` to the input limit, and
  refresh `0x14`/`0x15` at least every **175 s** or the part shuts down.
  **Done and verified this session** — see §3: the driver charges the pack at
  ~0.4 A (image `0xA0B75C43`).

## 1. The register set, from the vendor's own eval guide

Renesas/Intersil AN1570 (ISL9519TQFNEVAL2Z user guide, FN6773) gives the
operating rules that match the measurements:

| rule | consequence |
|---|---|
| Charge Current and Charge Voltage registers are `0x0000` at power-up and **the output is disabled**; valid non-zero values to both enable it | the Linux boot leaves the part disabled (nothing writes it) |
| "Write All" sends SMBus sequences to **registers 14, 15, 3F and 44** | `0x14` charge current, `0x15` max system voltage, `0x3F` input current, `0x44` control |
| **LO byte first, HI byte second** | 16-bit little-endian words (confirmed by the live reads) |
| the part **shuts down unless it receives MaxSystemVoltage or ChargeCurrent commands every 175 s** | the driver needs a periodic refresh timer |
| VendorID (reg `0xFE`) / DeviceID (reg `0xFF`) | `0x0049` / `0x0003` measured |

The register values are **masked engineering fields**, not 1 mA/mV codes
(static RE of RIM's `battery_win`, `isl_9519_update_regs` @ 0xB1B8):

| register | field | step | measured value | meaning |
|---|---|---|---|---|
| `0x14` charge current | bits 12:7 | 128 mA | `0x0280` | 640 mA |
| `0x15` max system voltage | bits 13:4 | 16 mV | `0x1070` | 4208 mV |
| `0x3E` min system voltage | bits 14:8 | 256 mV | `0x0D00` | 3328 mV |
| `0x3F` input current limit | bits 12:7 | 128 mA | `0x0180` | 384 mA |

RIM writes them in the order **`0x3E`, `0x15`, `0x14`, `0x3F`**, reads all
four back, and repeats every **~1.07 s**; that periodic rewrite is the
watchdog kick.  It reads `0x3D` as a liveness probe and **never touches
`0x44`** (or `0x16`).  The CC/CV/complete decisions are made outside the ISL
driver from the BQ27541/PMIC data — the ISL only enforces the open-loop
charge-current and max-system-voltage ceilings.

## 2. What this corrects

* **"The pack ran flat because the TWL6030 BCI was never instantiated."**
  The BCI is indeed never instantiated — but it is **not the charger**.  The
  BCI probe fix (session 31, `0x306E3DA5`) is correct work and harmless, yet
  it cannot charge anything: the charger is the ISL9519.
* **"The stock OS charges the pack."**  It does, through the ISL9519, and
  only when the input-current limit exceeds the system load.  On a host USB
  port 1917 sets 384 mA, below the ~430 mA load, so the net is slightly
  negative — consistent with the operator's observation that 2.1.0.1917 does
  not show charging on a PC port while 2.0.0.4869 did.
* **`HEALTH=Dead` in Linux was the gauge's SOCF flag**, not a failing pack:
  QNX reports `StateOfHealth 90` and `StateOfBattery::OK`, and the pack
  charged from 2 % to 7 % on the dock.

## 3. Executed on Linux — the driver works

The minimal driver is `drivers/power/supply/isl9519.c` (built-in,
`CONFIG_CHARGER_ISL9519=y`), with `charger@9 { compatible =
"intersil,isl9519"; }` under `&i2c1`.  It verifies VendorID/DeviceID, writes
the four registers in RIM's order using the field steps above, and refreshes
them every 5 s.  Image **`0xA0B75C43`**
(`local/images/kernel-0xA0B75C43-isl9519.img`), region-0 only (the region-1
rootfs is the session-31 charger rootfs, unchanged).

Measured on the first boot:

```
[    2.301452] PBR: 0-0009 <- isl9519
[    2.388519] isl9519 0-0009: ISL9519 charger: 640 mA charge, 3328/4208 mV system, 384 mA input
isl9519 uevent: STATUS=Charging ONLINE=1
                CONSTANT_CHARGE_CURRENT_MAX=640000
                CONSTANT_CHARGE_VOLTAGE_MAX=4208000
                INPUT_CURRENT_LIMIT=384000
bq27541-0: STATUS=Charging, CURRENT_NOW=+358000 → +397000 µA,
           VOLTAGE_NOW=3.775 → 3.789 V, CAPACITY=8 %
```

Register read-back matches the programmed values exactly: `0x14=0x0280`,
`0x15=0x1070`, `0x3E=0x0D00`, `0x3F=0x0180`, `0xFE=0x0049`, `0xFF=0x0003`.
The pack charges at ~0.4 A from a host USB port.  The TWL BCI node and
modules are left in place but are inert; they can be dropped later.
