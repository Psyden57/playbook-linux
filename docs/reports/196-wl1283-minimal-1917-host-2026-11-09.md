# 196 — The 1917-truth minimal `&mmc5` host: the one experiment (negative)

Date: 2026-11-09 (session 37, Linux-era 31).  Task 3 of `HANDOFF.md` §0c,
`DECISIONS.md` §46.

## 0. Headline

The 1917-truth minimal `&mmc5` host **boots and probes, and CMD5 still does not
answer.**  `mmc4` (the `480d5000` host) runs `sdio_reset` (CMD52) → `go_idle`
(CMD0) → `attach_sdio` and returns `attach_sdio no` at **2.829 s**, then
`Failed to initialize a non-removable card` at 2.831 s.  There is **no** "no
support for card's volts" warning, so the failure is inside CMD5, before
voltage selection — the DT model is not the missing piece, and the redo
reproduced the old state (reports 180–192).

The rest of the stripped base is healthy: the internal eMMC (`mmcblk1`,
`MCGAFA 59.4 GiB`, boot0/boot1/rpmb), the **Munin touch works** (`input` /
`event0`, bootloader id `0xb0`, app `0x020a`, build `0x3b`), the BMA150 and
the loop-mounted ext4 root are all up.  So archiving the WL1283 code
(session 37 Task 1) did not regress anything.

## 1. What was built and flashed

* The re-derived node is exactly report 195 §3.4: `sdmmc5_pins` (pads
  `0x148`–`0x152`, `PIN_INPUT_PULLUP | MUX_MODE0`), `wl1283_ctrl_pins` (pad
  `0x07c` = gpio_54 / WL_EN, `0x0003`), the `wl1283-en-hog` on gpio 22, WL_IRQ
  `0x07a` left as `bridge_pins` muxes it, `vmmc-supply = <&vwl1283>` (1.8 V OCR
  window), `bus-width = <4>`, `non-removable`, `ti,non-removable`, `no-sd`,
  `no-mmc`, `max-frequency = <24000000>`.
* **No** OCR quirk (`MMC_CAP2_SDIO_OCR_PROBE_FFFF00`), **no** FREF enable, **no**
  WL_EN reset pulse, **no** `mmc-pwrseq`, **no** init-clock override — all of
  those are the archived instrumentation and were negative in reports 180–192.
* Image **`0x0DC36A11`** (`0x91A514` bytes, < `0xB00000`, DTB 94 188 B), kernel
  `7.3.3 #24` (2026-11-09 10:56:42).  Flashed **region 0 only** (region 1
  unchanged; 588 frames; `COMPLETE 0x40C0 -> cmd 0x4006`).

## 2. The boot trace (the evidence)

```
[ 2.748291] PBC: mmc4 initial_voltage
[ 2.760070] PBSIO: mmc4 enter pm=2 clk=400000 bw=0
[ 2.788421] PBC: mmc4 try 400000Hz (f_min=400000 f_max=24000000 f_init=400000 ios.clock=400000)
[ 2.788970] PBC: mmc4 sdio_reset           <- CMD52
[ 2.793579] PBC: mmc4 go_idle              <- CMD0
[ 2.822845] PBC: mmc4 attach_sdio          <- CMD5
[ 2.829406] PBC: mmc4 attach_sdio no
[ 2.831634] mmc4: Failed to initialize a non-removable card
```

`max-frequency = <24000000>` took effect (`f_max=24000000`), but the init
phase runs at **400 kHz** (the MMC core's `f_init`), as Linux always does;
QNX's 24 MHz + CMD5 arg `0x00FFFF00` + no-CMD52 is H1 (report 192 §9), also
negative, and is **not** re-run here (DECISIONS §46: an overlapping test must
state what differs; the only difference would be the 1.8 V window that CMD5
never reaches).

No `mmc4:` voltage warning appears, so `mmc_select_voltage` was not the failing
step; the card never answered CMD5.  The trace is consistent with the prior
`err = -110` (timeout), which this image cannot print because the `PBCMD` /
`PBOCR` prints are archived (Task 1).

**The DT model is provably applied and 1917-identical.**  Read back on this
boot with `devmem` (`PBCON_TMO=12 pbcon.py …`):

| register | value | 1917 reference |
|---|---|---|
| `0x4A100148` / `0x14C` / `0x150` (sdmmc5 clk/cmd/dat0-3) | `0x0118` | `0x0118` (mux 0, pull-up, input) |
| `0x4A10007C` (WL_EN, gpio 54) | `0x0003` | `0x0003` (mux 3, output) |
| `0x4A10007A` (WL_IRQ, gpio 53) | `0x410B` | `0x410b` (mux 3, input, pull, falling) |
| `GPIO2_OE` (`0x48055134`) | `0xCE2ECDFF` | bit 22 out, bit 21 in |
| `GPIO2_DATAOUT` (`0x4805513C`) | `0x31413200` | `0x31413200` (WL_EN bit 22 high) |
| `GPIO2_DATAIN` (`0x48055138`) | **`0x01000010`** | QNX-with-WLAN-up has bit 21 = **1** |

So the pads, WL_EN level and IRQ direction match QNX bit-for-bit, **WL_EN is
high, and the chip still does not drive WL_IRQ** (bit 21 = 0) — exactly the
session-33 result (report 188), now with the 1917-truth DT.  The remaining
difference is inside the chip (its TCXO/VBAT/SLOW_CLK) or in OMAP HSMMC
sampling; no further DT or SoC-register change is expected to answer it.

Full log: `local/logs/boot-0x0DC36A11-1917mmc5.log` (1055 lines).

## 4. Conclusion and next measurement

The **1917-truth DT model is not the missing piece**: with every property
re-derived from the 1917 `/base` / startup-playbook / `devnp-ti1283.so`
(pads, WL_EN, WL_IRQ, 4-bit, 24 MHz, no host rail), the card is still silent
from CMD5.  Combined with reports 180–192 (pads/GPIOs/PMIC rails/`CLK32KG`/
clock manager matched; S3 and H1 negative), the remaining difference is
**chip-side or host sampling**:

* VBAT/VIO/TCXO (26 MHz) / SLOW_CLK (32.768 kHz) at the chip's BGA pins;
* MMC5 CLK / CMD / DAT0 with a logic analyser.

Both need a board/schematic view or a logic analyser, as reports 180–192
concluded.  A **new lead** to check the next time TabletOS is up (operator,
session 37): **NVRAM or a QNX-exposed partition may hold WLAN calibration /
NVS data** (per-unit MAC and TX calibration), which matters for the
post-enumeration `wl12xx` bring-up even though it cannot fix CMD5.  Read-only
inspection is allowed (NVRAM is read-only for us); see `SAFETY.md` §1.
