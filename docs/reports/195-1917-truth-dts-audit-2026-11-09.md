# 195 — The 1917-truth board-DTS audit (Task 2)

Date: 2026-11-09 (session 37, Linux-era 31).  Status: **Task 1 (archive) done;
this report is Task 2 (file-only audit).**  Task 3 (a minimal `&mmc5` host and
one boot) is next.

## 0. Headline

The board DTS header still said it was reverse-engineered from **2.0.0.4869**.
A node-by-node audit finds that **every functional node is now cited from
2.1.0.1917** — the live reference unit, the 1917 `/base` QNX6 image, the 1917
IFS tree, or a shipped 1917 blob — and the 4869-era claim is stale.  The audit
also found **three defects**, all corrected in this session:

1. the TWL6030 comment gave **I²C1 as `0x48072000`** (that is I²C2); I²C1 is
   `0x48070000` (report 183; the live `i2c-0`/`i2c-1` mapping, report 193 §1);
2. an I²C4 comment still called I²C3 "the unconfirmed touch bus" — the touch
   is on I²C2 (report 193, DECISIONS §44), so I²C3 is enabled-but-empty;
3. the board DTS header's "first-boot scope / no pinctrl nodes" text was
   obsolete (the file now has many pinctrl groups).

The **1917-truth `&mmc5` derivation** is §3.  It is the input to Task 3.

**Rule used throughout:** hardware facts come from OS 2.x only (trap 110,
DECISIONS §34).  The only 1917 blobs on disk are the live-reference reads
(recorded in reports 180–194), `local/work/rcfs-1917.rcfs` (the 1917 `/base`,
QNX6), `local/work/ifs1917.imagefs` + `local/work/ifs1917-tree`, and the
shipped libraries under `local/work/qnx-libs/` (e.g. `devnp-ti1283.so`,
`DATE=2013/01/17`).  The `local/work/bb10/...hwio-config-winchester.so` copies
are **BB10** (10.0.9.1103) and are **not** used for any fact here.

## 3. The 1917-truth `&mmc5` derivation

The archival question was whether a **wrong or missing DT model** (pads,
`vmmc`/`vqmmc`, pwrseq, clocks, bus properties) could explain the missing CMD5.
Every property below is derived from a 1917 source, not from the old node.

|---|---|---|

### 3.2 The pads (from `hwio-config-winchester.so` in the 1917 `/base`)

The pad database is `lib/dll/hwio-config-winchester.so` (13 968 B, dated
2013‑01‑15) in the **1917** `/base`; resolved through `hwio-omap4.so`.  This
session the 1917 `/base` image was **mounted read-only** (`bb10mt qnx6 mount
-i local/work/rcfs-1917.rcfs`) and the tables were read directly: the exported
`pad_config` is **248 × 20 B** (4 960 B) and `gpio_config` is **72 × 32 B**
(2 304 B), with `pad_config_size`/`gpio_config_size` = 248/72.  The 1917
`lib/dll/devnp-ti1283.so` hashes to `a5fd35de…`, identical to
`local/work/qnx-libs/devnp-ti1283.so`.  The WLAN rows (AF = alternate
function; the two halves of a 32-bit pad register are separate DT pads):

| DT pad | signal | AF | 1917 value | live read | citation |
|---|---|---|---|---|---|
| `0x148` | sdmmc5_clk | 0 | mux 0, pull-up, input | `0x0118` | report 189 §2.2; report 180 §1/§4 |
| `0x14a` | sdmmc5_cmd | 0 | mux 0, pull-up, input | `0x0118` | same |
| `0x14c` | sdmmc5_dat0 | 0 | mux 0, pull-up, input | `0x0118` | same |
| `0x14e` | sdmmc5_dat1 | 0 | mux 0, pull-up, input | `0x0118` | same |
| `0x150` | sdmmc5_dat2 | 0 | mux 0, pull-up, input | `0x0118` | same |
| `0x152` | sdmmc5_dat3 | 0 | mux 0, pull-up, input | `0x0118` | same |
| `0x07c` | **WL_EN** (gpio 54, `gpmc_nwp`) | 3 | mux 3, no pull, output | `0x0003` | report 189 §2.2/§2.3; live report 180 §4 |
| `0x07a` | **WL_IRQ** (gpio 53, `gpmc_ncs3`) | 3 | mux 3, input, pull, falling | `0x410b` | report 189 §2.2/§2.3; live report 180 §4 |

`WL_EN`/`WL_IRQ` are **not** part of the sdmmc5 pin group; `0x07a` is already
muxed by `bridge_pins` (as an input) and `0x07c` needs its own group.  There is
**no** WLAN rail-enable or clock-gate pad in the whole table (report 189 §2.2).

Direct read of the 1917 `gpio_config` (this session), records 13 / 14 (field
semantics from startup-playbook's `FUN_8010cb9c`, report 192 §3):

| idx | gpio | `+0x04` dir | `+0x0c` edge | `+0x11` pull/en | `+0x14` rev | `+0x16` phase | `+0x18` signal |
|---|---|---|---|---|---|---|---|
| 13 | 53 (WL_IRQ) | 0 (input) | 2 (falling) | 1 | 0–15 | 1 | `0x59` |
| 14 | 54 (WL_EN) | 1 (output) | 0 | 0 | 0–15 | 1 | `0x58` |

**Cross-checked against startup-playbook itself.**  The 1917 IFS
`startup.*` (imagefs `0x908`, `0x44008` B, sha256 `bc7d3a41…`) is raw ARM at
`0x80100000`; its Winchester GPIO table at image `0x80122750` (75 × 32 B)
holds **records 13/14 byte-identical to the hwio `gpio_config` records
above** (raw `35 00 00 00 00 00 00 00 00 00 00 00 02 … 59` and
`36 00 00 00 01 … 58`).  So `hwio-config-winchester.so` and startup-playbook
carry the same board table: **gpio 53 = input, falling; gpio 54 = output,
driven low at startup (the WLAN driver raises it).**  Its option strings are
`WLAN_EN_GPIO=54,WLAN_INT_GPIO=53` (plus the Colt/London pairs 151/152,
151/163), matching the syspage node.

**Correction to report 189 §2.1:** the report's `+0xC` "pull/attr" is the
**edge-detect** field (2 = falling) and its `+0x10` "detect" is the low byte of
the pull/enable word (the meaningful byte is **`+0x11`**); the pad signal id is
at **`+0x18`** (not `+0x1c`, which is zero).  The values report 189 gave
(signal `0x59`/`0x58`, falling for gpio 53) are right; the offsets/labels were
off by a field.  The pad table independently agrees: pad `0x35` (physical
`0x07a`) carries signal `0x59`, pad `0x36` (physical `0x07c`) signal `0x58`.

Wiring from the driver (report 180 §2): `WLAN_EN_GPIO=54` output, raised then
`delay(120)`; `WLAN_INT_GPIO=53` input, falling, active low
(`Hwinit IRQ polarity active low`).  The 1917 syspage `WLAN` node is exactly
`WLAN_EN_GPIO=54,WLAN_INT_GPIO=53` with an empty `location` (report 189 §8).

### 3.3 The regulator / I/O-voltage question (the one real subtlety)

The reference has **no host-side rail** for the WL1283; the chip is powered by
the bootloader and its VIO is **1.8 V** (measured; report 188).  Linux's MMC
core still needs a non-zero `ocr_avail`, and the board has no SD slot, so the
old node used a `regulator-fixed` **only** as an OCR window (not a rail).  The
archived value had drifted 1.8 V → 3.3 V (session 30 → 32).  The 1917-truth
value is **1.8 V** (`VS18`/`MMC_VDD_165_195`), matching the measured VIO;
`HCTL` must still read `0x00000b00` (SDVS18 | SDBP) and `CAPA` must keep VS18
(trap 133).  If a broader OCR is needed, the 3.3 V window is the documented
alternative — but that is a *different variable* and must be stated as such.

There is **no `ti,dual-volt`** on `mmc5` (only `mmc1` has it, trap 133), so
`omap_hsmmc` takes the non-dual-volt branch (`hctl = SDVS18; capa = VS18`).

### 3.4 The 1917-truth minimal node (proposed; Task 3)

Deliberately **no** OCR quirk (`MMC_CAP2_SDIO_OCR_PROBE_FFFF00`), **no** FREF
enable, **no** WL_EN reset pulse, **no** `mmc-pwrseq` — the reference has none of
these (the driver only raises EN and delays 120 ms; the reset strobe is a
driver action, not a board pinctrl/pwrseq).  `no-sd`/`no-mmc` match QNX sending
only CMD0/5/3/7.

```dts
	vwl1283: regulator-wl1283 {
		compatible = "regulator-fixed";
		regulator-name = "vwl1283";
		/* 1917 VIO is 1.8 V; this is an OCR window, not a rail. */
		regulator-min-microvolt = <1800000>;
		regulator-max-microvolt = <1800000>;
		regulator-always-on;
	};

	&omap4_pmx_core {
		sdmmc5_pins: sdmmc5-pins {
			pinctrl-single,pins = <
				OMAP4_IOPAD(0x148, PIN_INPUT_PULLUP | MUX_MODE0) /* clk  */
				OMAP4_IOPAD(0x14a, PIN_INPUT_PULLUP | MUX_MODE0) /* cmd  */
				OMAP4_IOPAD(0x14c, PIN_INPUT_PULLUP | MUX_MODE0) /* dat0 */
				OMAP4_IOPAD(0x14e, PIN_INPUT_PULLUP | MUX_MODE0) /* dat1 */
				OMAP4_IOPAD(0x150, PIN_INPUT_PULLUP | MUX_MODE0) /* dat2 */
				OMAP4_IOPAD(0x152, PIN_INPUT_PULLUP | MUX_MODE0) /* dat3 */
			>;
		};
		wl1283_ctrl_pins: wl1283-ctrl-pins {
			pinctrl-single,pins = <
				OMAP4_IOPAD(0x07c, 0x0003) /* gpmc_nwp = gpio_54 (WL_EN) */
			>;
		};
	};

	&gpio2 {
		/* append &wl1283_ctrl_pins to pinctrl-0 */
		wl1283-en-hog {
			gpio-hog;
			gpios = <22 GPIO_ACTIVE_HIGH>;
			output-high;			/* WL_EN, 1917: raised then 120 ms */
			line-name = "wl1283-enable";
		};
	};

	&mmc5 {
		status = "okay";
		pinctrl-names = "default";
		pinctrl-0 = <&sdmmc5_pins>;	/* WL_IRQ 0x07a is in bridge_pins */
		vmmc-supply = <&vwl1283>;
		bus-width = <4>;
		non-removable;
		ti,non-removable;
		no-sd;
		no-mmc;
		max-frequency = <24000000>;	/* 1917: 96 MHz / (2·2) */
	};
```

`WL_IRQ` (`0x07a`) stays as muxed by `bridge_pins` (input, pull, `0x410b`); the
minimal host does not register an SDIO interrupt handler (the old driver polls
and the IRQ is a later variable, like the touch's inferred `tp_intr`).

### 3.5 What is *not* claimed

* The 1917-truth node does not explain why CMD5 did not answer; reports 180–192
  already eliminated pads, GPIOs, PMIC rails, `CLK32KG`, the clock manager and
  the exact QNX sequence.  The re-derivation's purpose (§46) is to rule out a
  **wrong DT model** — and the model above differs from the archived one only in
  the vmmc window (1.8 vs 3.3 V), `max-frequency` (added), `no-sd`/`no-mmc`,
  `ti,non-removable` (added), and the **absence** of the OCR/FREF/pulse code.
* Every overlapping test must state what differs (DECISIONS §46), and stay one
  variable per boot.
