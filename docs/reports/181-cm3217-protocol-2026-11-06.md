# 181 — The CM3217 is not a register device: two slave addresses, bare bytes, no ID

**Session 29 (absolute), Linux-era 23.  2026-11-06.**
Status: **static RE only** (`local/work/qnx-libs/ls-cm3217.so`).  No device access,
no writes.

This settles the open question from report 178 / trap 95: why the mainline
`cm32181` sequence is refused by the PlayBook's ambient-light sensor.  The
answer is not a chip-ID mismatch — **the vendor driver never addresses a
register at all**, and the 16-bit ALS value is split across **two 7-bit slave
addresses**.

---

## 0. The protocol, in one table

| what | value | evidence |
|---|---|---|
| I²C bus | QNX `/dev/i2c3` (OMAP I²C4 `0x48350000`), **400 kHz** | `/dev/i2c` + `3`, `DCMD_I2C_SET_BUS_SPEED` ×2 with 400000 |
| **MSB of the ALS count** | slave **0x10**, a bare **1-byte read** | `readLightRegisters` @0x2754 |
| **LSB of the ALS count** | slave **0x11**, a bare **1-byte read** | read *first*, but combined as `(b10 << 8) \| b11` |
| enable / measure | write **`cmd1` = 0x26** to **0x10** | `ls_startup` @0x2874 |
| shutdown | write **`cmd1 \| 1` = 0x27** to **0x10** (bit 0 = ALS off) | `ls_shutdown` @0x2948 |
| config byte | write **`cmd2` = 0x60** to **0x11** at init | `initCM3217` @0x2cf8 |
| integration time | `(IT_TABLE[cmd2>>5] >> 1) << cmd1[3:2]` ms; table 800/400/266/**200**/130/100/80/66 ⇒ default **200 ms** | `cm3217_getIntegrationTime` @0x1360 |
| register index | **there is none** — every transfer is `START, (addr<<1)\|R/W, 1 byte, STOP` | every `devctl()` site: only `DCMD_I2C_RECV` (0xC0100506), `DCMD_I2C_SEND` (0x80100505), `DCMD_I2C_SET_BUS_SPEED` |
| ID register | **never read or checked** | no code path can send a register index (the length is a fixed static 1) |
| interrupt pin | none — polled on demand from a PPS object | no `InterruptAttach*` import; `ionotify()` on `/pps/services/light_sensor/status` |
| settle time | ~**200 ms** after enable before a sample is trusted | `cm3217_calibrate` sweeps delay = 200 ms + 10·n ms, n = 0..19 |

`0xC0100506` is **not** an I²C message array — it is QNX `DCMD_I2C_RECV` for
`i2c_recv_t` (16-byte header, +1 payload byte, `nbytes = 17`), i.e. plain
`DCMD_I2C_SEND`/`DCMD_I2C_RECV` with `I2C_ADDRFMT_7BIT`.  `DCMD_I2C_SENDRECV`
is never used, so there is **no repeated start and no "write cmd, read data"**
shape anywhere.

---

## 1. Why the mainline driver fails

`cm32181.c` does `regmap`-style reads: `START, 0x20, reg 0x04, REPEATED-START,
0x21, <2 bytes>, STOP`, and it rejects chips whose ID (reg 0x07/0x0C) is not
0x18/0x81/0x82.  This part:

* has no register file over I²C at all — a register byte sent to it is just a
  stray command, which is why report 178 saw a byte read of 0x04 give `0x4d`
  once and `0x00` afterwards, a word read give `0xff00`, and a word write of
  CMD `0x0800` return `ENXIO`;
* answers at **two** addresses (0x10 = MSB + command, 0x11 = LSB + config);
* is left **powered down** (`0x27`) by the vendor driver until a measurement is
  requested, and needs ~200 ms after `0x26` before its count is meaningful.

So a CM3217 driver is a small standalone driver, not a `cm32181` ID patch.

## 2. Calibration

`cal_table_IT200MS` (19 × `{u32 lux; u32 adc;}`) is applied as
`lux = entry.lux * raw / entry.adc` after a binary search for the bracket
(`cm3217_adc_to_lux` @0x1c5c).  The table:

```
lux:      0  1  2  4  8 16 32 64 128 256 512 1024 2048 4096 8192 16384 32768 65536 131072
adc:      0  1  1  2  4  8 17 34  67 135 269  538 1077 2154 4308  8615 17231 34461  65535
```

A mainline-style driver can carry the same table, or just report the raw count
and scale later.

## 3. What a Linux driver needs

```c
/* one i2c_client at 0x10, one at 0x11 (or two i2c_new_dummy_device on the same adapter) */
#define CM3217_CMD1_ENABLE   0x26   /* -> 0x10 */
#define CM3217_CMD1_SHUTDOWN 0x27   /* -> 0x10, bit0 = ALS off */
#define CM3217_CMD2_DEFAULT  0x60   /* -> 0x11 */
/* measure: write 0x26 to 0x10; msleep(200); lo = i2c_smbus_read_byte(0x11);
   hi = i2c_smbus_read_byte(0x10); raw = (hi << 8) | lo; write 0x27 to 0x10 */
```

`i2c_smbus_read_byte()` is exactly a bare 1-byte read (`START, addr|R, byte,
STOP`), so it matches the vendor shape — **do not** use `i2c_smbus_read_word_data`
or `regmap`, and do not send a register index.

**Not determinable from the binary:** what the chip does with the byte written
to 0x10/0x11 is inferred from the vendor's own sequencing and the CM3218x
family; the `msb::`/`lsb::` PPS attributes are raw command pokes and can be used
on TabletOS to confirm the two bytes live.
