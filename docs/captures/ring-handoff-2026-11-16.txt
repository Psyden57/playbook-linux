# Ring hand-off and the SMP early-death logs — 2026-11-16 (session 62)

Raw evidence behind report 255.  Everything here was read from the unit through
`tools/bench/ringdump.c` (an `mmap` of `/dev/mem`; `dd if=/dev/mem` fails on the
`no-map` pages), dumped to `/tmp` and pulled over ssh.  The host-side files are
`local/work/r2{b,c,e,f,g,h}.bin` (gitignored); this file records the decoded
facts so they survive.

The chainloader that produced these boots is the session-62 one: ring2
(`0x90000000` = `BC_PRIMARY`) carries an append-only character stream, `count` at
`+0x80`, `index` at `+0x84`, a `RHND` record at `+0xb8` with the last two entry
headers (`+0xbc..+0xc8`) and the previous boot's timing
(`+0xcc` pre-jump CRR, `+0xd0` kernel-entry CRR, `+0xd4` entry stamp).

## 1. `+0x1000` is the ring's character array, not a window

Live ring2 on the bench image (the region-1 kernel, `#79`):

```
count = 71103 (0x115BF)     index = 6079 (0x17BF) = 71103 mod 0x7F00
buffer at +0xE80 .. +0x11C0 (i.e. characters 0xE80..0x11C0 of the page):
  …ime
  [    9.624053] module kpp: .gnu.linkonce.this_module section size must match …
  [    9.628753] module kpp: .gnu.linkonce.this_module section size must match …
  [    9.633453] module ecdh_generic: .gnu.linkonce.this_module section size must …
```

The text flows straight across `+0x1000` (character #3840) mid-line with
increasing timestamps.  The wrap seam is at the write index:

```
position 6079:
  [   34.402374] audio-ldo: disabling        <- newest
  ] of_get_named_gpiod_flags: parsed 'gpio' …  <- oldest (≈2.8 s)
```

Offsets inside a boot log explain both session-61 captures: `mobility grouping`
at **3822**, `SLUB:` at **3959**, `RCU calculated` at **4294** — so `+0x1000`
starts mid-`grouping on.  Total pages:` in every SMP log, and a 3943-character
boot leaves `mem auto-init…` there while a 4986-character one leaves
`SLUB`+`RCU`.

## 2. One ring, many boots (plain SMP `#78`, `0x202E9F38`)

The append-only ring split at every `Uncompressing Linux` fragment (11 segments
still in the 32 KiB window):

| characters | last line of that boot |
|---|---|
| 3208 | `On node 0, zone HighMem: 512 pages in unavailable ranges` |
| 3943 | `mem auto-init: stack:all(zero), heap alloc:off, heap free:off` |
| 3943 | same |
| 4986 | `rcu: PBDBG: rcu_init done` |
| 50 | `Uncompressing Linux... done, booting the kernel.` |
| 50 | same |
| 3943 | `mem auto-init…` |
| 50 | same |
| 3943 | `mem auto-init…` |
| 4211 | `…RCU calculated value of scheduler-enlistment delay is 10 jif` (truncated) |
| 50 | same |

So one and the same image stops at 3208 / 3943 / 4211 characters — the
signature of a time cut, not a statement-level hang (§4).
