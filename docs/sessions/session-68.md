## Confirmed (measured, read in a file, or seen on the bench)

### Why a Wayland client was software (report 269 §1–§2)

* **catacomb serves no `wl_drm`.**  `WAYLAND_DEBUG=1` on a client lists its
  globals (`wl_shm`, `zwp_linux_dmabuf_v1`, layer-shell, …) and no `wl_drm`.
* **Mesa 21.3.9's Wayland EGL platform needs it.**  `dri2_initialize_wayland_drm()`
  bails at `dri2_dpy->wl_drm == NULL` (`platform_wayland.c:1567`);
  `eglInitialize()` then retries with `ForceSoftware = TRUE`
  (`eglapi.c:640`) and `dri2_initialize_wayland_swrast()` loads `swrast_dri`,
  so `MESA_LOADER_DRIVER_OVERRIDE=pvr` is never consulted (it is read only by
  `loader_get_driver_for_fd()`, `loader.c:478`).  Measured both ways: the first
  EGL debug line is `MESA-LOADER: dlopen(…/swrast_dri.so)`, and `epitaph`
  reports `softpipe`.
* **The GBM/surfaceless path works:** `tools/bench/gbmtest2.py` on
  `renderD129` → EGL 1.4, 12 window configs, `PowerVR SGX 540`,
  `EGL_MESA_image_dma_buf_export`; surfaceless the same.  The driver/kernel
  side was healthy all along.
* **Smithay itself implements no `wl_drm`** (its source tree has no such
  module), so catacomb could not enable one by configuration.

### The wlroots proof (report 269 §4a–§4b)

* **Stock phoc 0.59** opened the seat, the DRM backend on `card0` (omapdrm)
  and the GLES2 renderer on the SGX (`GL renderer: PowerVR SGX 540`), then died
  at `GL_EXT_unpack_subimage not supported` — exactly what pvrports' patch
  fixes.
* **pvrports' phoc 0.52.rc1** (`pkgrel=9992`, built from the local pmaports)
  creates its renderer, modesets LVDS-1 at 1024x600, and advertises `wl_drm`.
  A Wayland-EGL client under it with the override reports `PowerVR SGX 540` and
  maps `pvr_dri`; without the override, `softpipe`/`swrast_dri`.

### The chosen fix and what it does/does not do (report 269 §4c–§4f)

* **A PRIME-only `wl_drm` in catacomb** (`src/protocols/wl_drm.rs`, generated by
  `wayland_scanner::generate_server_code!` from `protocols/wayland-drm.xml`):
  it sends the render node, ARGB8888/XRGB8888 and `capabilities(PRIME)`;
  `authenticate` is acknowledged (Mesa marks a render node authenticated
  itself); `create_prime_buffer` builds a `Dmabuf` and `data_init.init`s a
  `wl_buffer` with it as user data, which Smithay's `buffer_type()`/import path
  treats like a `zwp_linux_dmabuf_v1` buffer.  GEM-name requests are rejected.
  No Smithay change.
* Shipped as **catacomb 1.5.0-r10002** (`wl-drm-prime.patch`, 432 lines; the
  APKBUILD applies it before `cargo fetch --locked`; APK sha256
  `5fdf7a1c…`, 2,079,579 B).  It compiles natively (`cargo check`, clean),
  installs over the live root, and a clean `reboot -f` keeps it.
* **What works (selection):** `WAYLAND_DEBUG=1` shows
  **`global(32, "wl_drm", 2)`**; `tools/bench/waylandtest.py` under catacomb →
  12 ES2 configs, `PowerVR SGX 540`, `pvr_dri`; `epitaph` logs `GL renderer
  "PowerVR SGX 540"`; `catacomb`/`tabula`/`epitaph` map `pvr_dri`; their
  buffers are linear `AR24` (1024x20 and 1024x585, **stride 4096**,
  `modifier: Invalid`, `node: None`) and `import_dmabuf` succeeds (trace).
* **What does NOT work (presentation):** a **`grim` capture of the compositor
  is black except its own chrome** (the gesture bar), and the operator saw a
  black screen.  The same clients on `wl_shm` (override unset) **do** display.
  `catacomb` is on the SGX; the client textures are imported but sample black.
  Cause not yet separated (client render not in the shared buffer, or a black
  pvr texture sample).  Report 269 §4e–§4f, trap 346.
* **Safe operational state:** `/etc/catacomb/initrc` **unsets
  `MESA_LOADER_DRIVER_OVERRIDE` for its children** (backup
  `/etc/catacomb/initrc.session68-pvr`), so the compositor keeps the SGX and
  the clients use `wl_shm`/softpipe; the desktop displays (wallpaper, status
  bar, keyboard; verified with `grim`).
* The override is still required **for the compositor** (the DRM-name
  heuristic does not map `pvrsrvkm` to `pvr`); tinydm exports it from
  `/usr/share/tinydm/env-wayland.d/60-pvr.sh`, login shells from
  `/etc/profile.d/mesa.sh`.

## Inferred (reasoning from evidence)

* **The open stack would remove the `wl_drm` requirement.**  Mesa 26.2.5's
  Wayland EGL platform first asks `zwp_linux_dmabuf_v1` for default dmabuf
  feedback and maps `main_device` to a render node
  (`platform_wayland.c:2167`, `:2629`); `wl_drm` is only the fallback.  catacomb
  already advertises `zwp_linux_dmabuf_v1` v5, so `powervr_sgx` + a current Mesa
  could work under catacomb unchanged — but SGX540 support is the project.
  Strong (source-read), not bench-tested.
* **The client/dmabuf path is the remaining suspect.**  The import succeeds and
  the buffer is linear; the failure is specific to pvr-rendered client buffers
  under catacomb (shm works).  Moderate; not separated into client-side vs
  compositor-side.
* **The pvr render node choice matters** (the bind-mount made the clients exit),
  but the exact correct node/feedback pairing is not established.

## Dead ends and wrong assumptions (valuable — do not skip)

* **"Install Phosh" was the wrong first move.**  It is pvrports' supported UI,
  but 358 packages / +323 MiB is wrong for 1 GB (operator).  The fix belongs in
  the existing lightweight compositor.
* **"A custom Qt Wayland client will sidestep it" is false** for the closed
  stack: Qt clients use Mesa's wayland platform too, and a Qt compositor serves
  no `wl_drm` either.  Only a `wl_drm`-serving compositor (or EGL device/GBM +
  linux-dmabuf in the client) gets the SGX.
* **"The override is enough"** — it is not, on catacomb: the swrast fallback
  never reads it.  It is necessary but only after `wl_drm` exists.
* **"The clients are on the GPU" — WRONG as written.**  I inferred it from
  `GL_RENDERER`/`maps`, then the `grim` capture and the operator showed the
  client surfaces are black.  Selection ≠ presentation.  Report 269 §4e was
  corrected in place; trap 346 records the lesson: **capture the framebuffer**.
* **The pvr render-node bind-mount (`renderD129` over `renderD128`) is not a
  fix.**  It made `tabula`/`epitaph` **exit** after logging their renderer (the
  session kept only shm clients); the bind was reverted (`target is busy` until
  tinydm was stopped).  Measurement: `ps` no longer listed them; the capture
  showed only the keyboard.
* **`tabula` under phoc** failed with `Broken pipe` (protocol mismatch) and
  `grim` reported `failed to screenshoot all sources`, so that comparison was
  inconclusive; a phoc-compatible presenting client is still needed.
